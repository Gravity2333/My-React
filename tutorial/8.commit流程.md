# completeWork 流程

commit 阶段分成两个子阶段 分别为

1. Mutation 阶段，处理 flags，收集 Effect，卸载 Ref
2. Layout 阶段 更新 Ref 处理 useLayoutEffect

commit 阶段由 workLoop 中的 commitRoot 函数完成，其流程为

1. 获取当前 renderLane 并且将其从 root 上移除 即 markRootFinished
2. 开启 Effect 调度，将 flushPassiveEffect 函数推入 scheduler.scheduleCallback 并且设置优先级为 NormalPriority
3. 检查 HostRootFiber 的 subTreeFlags，如果存在表示有副作用
4. 存在副作用，开启 Mutation 阶段 执行 commitMutationEffect，开始处理 flags
5. 把 root.current 改成当前已经完成处理的 finishedWork
6. 开启 Mutation 阶段，处理 Ref
7. 执行完成 ensureRootIsScheduled(root); 确保继续调度

## Mutation 阶段

Mutation 阶段会检查 HostRoot

1. 是否包含 flags 副作用
2. 子节点 subTreeFlags 是否包含副作用
   如果包含，那么调用 commitWork.ts 中的 commitMutationEffect

### commitMutationEffect

这个函数由 commitEffect 函数组合 commitMutationEffectOnFiber 完成
commitEffect 是个高阶函数，其接受 mask callback 返回一个函数

这个函数接受当前 commit 的 HostRootFiber 即 finishedWork 以及 root，并且开始深度优先搜索，如果深度搜索到某个节点的 subTreeFlags & mask = 0 那么就回溯

回溯的过程会调用 callback 处理节点副作用(副作用是在回溯阶段处理的!)

```typescript
function commitEffect(
  phrase: "mutation" | "layout",
  mask: Flages, // 当前更新的 Flags
  callback: (wip: FiberNode, root: FiberRootNode) => void // 归阶段调用的函数
) {
  return (finishedWork: FiberNode, root: FiberRootNode) => {
    let currentNode = finishedWork;
    while (currentNode !== null) {
      if (
        currentNode.subtreeFlags & (mask !== 0) ||
        currentNode.child !== null
      ) {
        // 递
        currentNode = currentNode.child;
        continue;
      } else {
        // 归
        while (currentNode.sibling === null) {
          callback(currentNode, root);
          if (currentNode === finishedWork) return;
          currentNode = currentNode.return;
        }
        currentNode = currentNode.sibling;
      }
    }
  };
}
```

### commitMutationEffectOnFiber

这个函数就是在一个 Fiber 节点上处理 flags 副作用，其作为 commitEffect 的 callback 参数传入！

这个函数会根据 flags 的类型来调用不同的处理函数来处理副作用

会处理 Placement Update ChildDeletion Ref 卸载 PassiveEffect 即 commit 收集

```typescript
/** 用来处理 Mutation副作用 [Placement | Update | ChildDeletion // TODO PassiveEffect] */
const commitMutationEffectsOnFiber: CommitCallback = (finishedWork, root) => {
  // 处理每个节点的Effect
  // 获取节点的flags
  const flags = finishedWork.flags;

  if ((flags & Placement) !== NoFlags) {
    // 存在Placement
    // 处理placement
    commitPlacement(finishedWork);
    // 去掉副作用flag
    // 去掉某个flag: 0b0111&(~0b0100) => 0b0111&0b1011=> 0b0011 去掉了 0b0100
    finishedWork.flags &= ~Placement;
  }

  if ((flags & Update) !== NoFlags) {
    commitUpdate(finishedWork);
    finishedWork.flags &= ~Update;
  }

  if ((flags & ChildDeletion) !== NoFlags) {
    const deletion = finishedWork.delections;
    deletion.forEach((deleteOldFiber) => {
      commitDeletion(deleteOldFiber, root);
    });
    finishedWork.flags &= ~ChildDeletion;
  }

  if ((flags & PassiveEffect) !== NoFlags) {
    // 存在被动副作用
    commitPassiveEffect(finishedWork, root, "update");
  }

  // 卸载Ref 只有hostComponent需要卸载
  if (finishedWork.tag === HostComponent && (flags & Ref) !== NoFlags) {
    const current = finishedWork.alternate;
    if (current) {
      // 需要卸载current的ref 其实本质上current和finishedWork的ref都是一个
      saftyDetachRef(current);
    }

    // 卸载之后由于可能还会加载ref 所以这里的flag不能~Ref
  }
};
```

### 处理节点 Placement - commitPlacement

这个函数做了三件事

1. 找到当前插入 Fiber 节点的真实 HOST parent 节点 对应函数 findParent
2. 找到当前插入 Fiber 节点的下一个兄弟节点 对应函数 findSibling
3. 调用 insertOrAppendPlacementNodeIntoContainer 即把当前就节点插入或者增加到容器节点内

```typescript
function commitPlacement(wip: FiberNode) {
  const parent = findParent(wip);
  const sibling = findSibling(wip);
  if (parent !== null) {
    insertOrAppendPlacementNodeIntoContianer(wip, parent, sibling);
  }
}
```

### findParent 找到 Host 父节点

这个函数用来找到当前待插入节点的父节点，其难点在于，需要向上找到最近的 tag 为 Host 的节点的 stateNode

```typescript
function findParent(wip: FiberNode) {
  let parent = wip.return;
  while (parent !== null) {
    if (parent.tag === HostComponent) {
      return parent.stateNode;
    }

    if (parent.tag === HostRoot) {
      return parent.stateNode.container;
    }

    node = node.return;
  }
}
```

### findSibling 找到兄弟节点

findSibling 的难点在于
需要找到当前待插入节点的下一个 Host 类型的兄弟，注意这个兄弟不一定是当前节点的亲兄弟，也可能是其祖先节点的兄弟，并且这个兄弟的 flags 不能是 Placement 也就是这个兄弟的 Fiber.stateNode 对应的真实 DOM 节点 必须已经挂载到 DOM 树上了

其过程和深度优先搜索相反，即先归回溯，后递

1. 从当前节点开始，找兄弟节点，如果不存在兄弟节点，就像上找父节点，直到找到到存在兄弟节点的祖先节点或 tag 类型为 Host 的节点（找到 parent 或者 root 节点停止）
2. 如果存在兄弟节点，就从兄弟节点开始向下找，如果找到 Host 节点，直接返回其 stateNode
3. 如果遇到 flag 为 Placement 的节点 或者找到叶子节点都不存在 Host 节点，就从当前节点回溯

```typescript
function findSibling(wip: FiberNode) {
  let node = wip;
  while (node !== null && node.tag !== HostComponent && node.tag !== HostRoot) {
    if (node.sibling === null) {
      // 归
      node = node.return;
      continue;
    } else {
      // 递
      node = node.sibling;
      while (node.tag !== HostComponent || node.tag !== HostText) {
        if (node.flags & (Placement !== NoFlags)) {
          continue;
        }
        node = node.child;
      }

      if (node & (Placement === NoFlags)) {
        return node.stateNode;
      }
    }
  }
}
```

### insertOrAppendPlacmentNodeIntoContainer

这个函数传入当前 Fiber 节点，及子节点和兄弟节点，将当前节点对应的所有真实 DOM 插入 / 追加到 parent 节点（container）中

难点在于，当前插入的节点可能不是 Host 节点，如果是 Fragment 或者 FunctionComponent 需要递归调用 insertOrAppendPlacmentNodeIntoContainer 处理其所有的子节点

```typescript
function insertOrAppendPlacementNodeIntoContainer(
  wip: FiberNode,
  parent: Container,
  sibling?: Element
) {
    if(wip.tag === HostComponent || wip.tag === HostText){
        parent.insertBefore(wip.stateNode,sibling)
    }else{
        // 如果不是Host类型，需要递归处理其所有子节点
        let child = wip.child
        while(child !== null){
            insertOrAppendPlacementNodeIntoContainer(child,parent,sibling)
            child = child.sibling
        }
    }
}
```

## 删除节点 commitDeletion
这个方法和insertOrAppendPlacementNodeIntoContainer正好反着，这个是删除当前节点
如果当前节点不是Host节点，需要把当前节点的所有“一层”的Host节点都删除,需要递归处理

```typescript
function commitDeletion(wip: FiberNode){
    const parent = findParent(wip)
    if(parent!==null){
        deleteNodeFromContianer(wip,parent)
    }
}

function deleteNodeFromContainer(wip: FiberNode,parent: Contianer,root: FiberRootNode){
    if(wip.tag === HostComponent || wip.tag === HostText){
        parent.removeChild(wip)

        // 卸载时，需要处理Ref
        // 只有Host节点有Ref
        if(wip.flag & Ref !== NoFlags){
            saftyDetachRef(wip)
        }
    }else{
        // 函数节点才有Effect 这里收集Effect
        if(wip.tag === FunctionComponent){
            commitPassiveEffect(wip, root, "unmount")
        }
        // 递归处理子节点
        let child = wip.child
        while(child!==null){
            deleteNodeFromContianer(child,parent)
            child = child.sibling
        }
    }
}
```

### 卸载Ref
卸载Ref通过 saftyDetachRef 完成，需要注意 Ref的标记在render beginWrok阶段
通过判断Ref是否改变或者新增FIber节点是否传递ref属性来标记Ref

Ref的卸载在Mutation阶段，即 如果fiber卸载 或者 fiber的ref变动，在此处给ref赋null或传入null （ref是函数的情况） 此阶段不会 remove Ref的flag

Ref的更新是在Layout阶段，给flag为Ref的Fiber赋新的DOM

注意 saftyDetachRef需要卸载的是 current 也就是 alternate上的Ref 需要传入current
```typescript
function saftyDetachRef(current: FiberNode){
    const ref = current.ref
    if(ref=== null) return 

    if(typeof ref === 'function'){
        ref(null)
    }else{
        ref.current = null
    }
}

```

## Layout阶段
Mutation阶段之后，还剩下Ref 需要挂载，此时current已经指向finishedWork 并且新的渲染任务已经被加入到更新队列。

此时进入Layout阶段，为什么在Layout阶段处理Ref，因为Layout阶段时还没有进行渲染，此时可以直接从任务队列中，获取新的未渲染的DOM对象，当渲染开始之后，这个对象可能由于渲染还没有结束，不一定能拿到

Layout阶段通过函数 commitLayoutEffect 完成，类似于commitMutationEffect 其也是调用高阶函数 commitEffect 返回一个函数

这个函数调用的callback为 commitLayoutEffectOnFiber 并且 mask为Ref

和Mutaion阶段一样 Layout阶段也进行一遍深度优先，对存在Ref的阶段调用 saftyAttachRef

### saftyAttachRef
在卸载Ref阶段，并没有去掉Fiber上的Ref flag 就是为了在Layout阶段 还要用这个flag来挂载新的Ref

saftyAttachRef挂载的节点为 finishedWOrk 即 新的Fiber节点

```typescript
function saftyAttachRef(finishedWork: FiberNode){
    const ref = finishedWork.ref
    const stateNode = finishedWork.stateNode
    if(ref === null )return
    if(typeof ref === 'function'){
        ref(stateNode)
    }else{
        ref.current = stateNode
    }
}
```
