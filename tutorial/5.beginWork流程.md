# BeginWork 流程
render阶段分成递，归 两个过程，两个流程交替进行，在workLoop中控制，在wip叶子节点之后会切换归的过程向上回退，其中递的过程为 beginWork 归的过程为 completeWork。

递的过程代码你可以在 [/lib/react-reconciler/beginWork.ts](../lib/react-reconciler/beginwork.ts)中找到。

## beginWork 函数
beginWork做的事情很简单
1. 判断当前更新到的Fiber节点是否符合bailout条件，如果符合 提前熔断，优化渲染性能
2. 根据fiber的tag属性，判断fiber类型，不同类型的fiber调用不同类型的处理函数 
其实现逻辑如下

```typescript
/** 递的过程 */
export function beginWork(wip: FiberNode, renderLane: Lane): FiberNode | null {
  /** bailout策略
   *  四要素
   *  1. props相等
   *  2. state相等 （无update -> update结果不变）
   *  3. type相等
   *  4. context相等 TODO
   */
  // 重置didReceiveUpdate
  didReceiveUpdate = false;

  // 获取current
  const current = wip.alternate;

  if (current !== null) {
    /** 更新模式下 才检查是否bailout */
    /** 检查props和type */
    const prevProps = current.memorizedProps;
    const wipProps = wip.pendingProps;
    /**
     * 注意 bailout的props直接检查对象地址是否相等
     * 如果父节点存在更新 那么子节点无法bailout 需要通过childReconcile创建
     * 那么子节点的 props一定和current.props不一样 因为createElement中传入的对象也不是相同地址 比如
     * current createElement('div',{a:100}) -父节点不同，导致reconcilechild-> createElement('div',{a:100})
     * 注意 虽然都是{a:100} 但是两个对象来源于两次render 其对象地址不同，这也就导致如果父节点没能bailout 子节点也无法bailout 就必须使用memo来shallowEqual
     */
    if (prevProps !== wipProps || current.type !== wip.type) {
      // 检查不通过
      didReceiveUpdate = true;
    } else {
      // 如果props和type都检查通过 检查state和context TODO
      if (!checkUpdate(wip, renderLane)) {
        // 进入bailout
        didReceiveUpdate = false;
        return bailoutOnAlreadyFinishedWork(wip, renderLane);
      }
    }
  }

  /** 给wip.lanes 置空
   *  当存在跳过的update时，processQueue的onSkipUpdate回调会返回跳过的lane 再次加上即可
   */
  wip.lanes = NoLane;

  // 比较，当前的fiber 和 旧的fiber
  switch (wip.tag) {
    case Fragment:
      return updateFragment(wip);
    case MemoComponent:
      return updateMemoComponent(wip, renderLane);
    case HostRoot:
      return updateHostRoot(wip, renderLane);
    case HostComponent:
      return updateHostComponent(wip);
    case HostText:
      return null;
    case FunctionComponent:
      return updateFunctionComponent(wip, wip.type as Function, renderLane);
    default:
      console.warn("beginWork未实现的类型", wip.tag);
      break;
  }
  return null;
}
```

## 更新根节点 updateHostRoot
首先来看一下跟节点类型Fiber的更新流程，也就是HostRootFiber的更新
在updateContainer函数中，出实话的element被加入到HostRoot Fiber节点的updateQueue中，并且把同步优先级lane加入到root.pendingLanes

由于同步优先级最高，所以第一次渲染的时候，一定是先渲染此次更新，也就是初始化

前面说了render阶段深度优先的流程，第一个被遍历到的节点是HostRoot

所以 updateHostRoot做的事情很简单，就是从updateQueue中获得updateContainer放入的element元素，并且开启reconciler（Diff）流程，实现如下:

```typescript
/** 处理HostRoot节点的比较 */
function updateHostRoot(wip: FiberNode, renderLane: Lane): FiberNode {
  /** 对于HostRoot节点 其memorizedState存储的是其children Element 因为其在dom/jsx中没有对应的节点，所以不存在props.children
   * 将其children放在memorizedState
   */
  const preChildren = wip.memorizedState;
  /** 获取updateQueue */
  const updateQueue = wip.updateQueue;
  /** 这里hostRoot的update由updateContainer放入，其对应的action就是其element */
  const { memorizedState: newChildren } = updateQueue.process(renderLane);
  /* 重新存储memroizedState */
  wip.memorizedState = newChildren;
  if (newChildren === preChildren) {
    // bailout
    bailoutOnAlreadyFinishedWork(wip, renderLane);
  }

  /** 协调其子节点 */
  reconcileChildren(wip, newChildren);

  /** 返回下一个待处理节点 即wip.child */
  return wip.child;
}
```
updateQueue是一个环形队列，process函数就是处理其所有的项，由于updateContainer中，只放入了element，所以这个newChildren也是这个element

wip.memorizedState用来存储上一次的children，如果地址相等，则进入bailout逻辑。

reconcileChildren用来开启协调，diff对比当前fiber和其新的children 复用/新建 最后把当前fiber下的所有children fiber都创建完，最后返回第一个child，继续递的流程！

## 更新HostComponent 和 HostText等原生节点
对于HostText 由于其本身是叶子节点，不需要beginWork流程，遇到HostText直接返回null，开启归的流程

HostComponent的更新也很简单，由于每次更新，HostComponent的children一定是通过children属性传入的

注意 当你使用 
```typescript
<div><child/></div>
```
时，本质就是传入到Props  
```typescript
<div children={<child/>}/>
```

同时，对于HostComponent节点才有Ref (这里我们不实现ClassComponent)，所以这里还需要标记Ref

所以对于HostComponent来说，其工作就是
1. 通过Props取得children元素
2. 标记Ref
3. 开启reconileChildren Diff生成子元素
实现如下:
```typescript
/** 处理普通节点的比较 */
function updateHostComponent(wip: FiberNode): FiberNode {
  /** 1.获取element.children */
  const hostChildren = wip.pendingProps?.children;
  // 目前只有在HostComponent中标记Ref
  markRef(wip);
  /** 2. 协调子元素 */
  reconcileChildren(wip, hostChildren);
  /** 3.返回第一个child */
  return wip.child;
}
```

## 更新函数节点 - updateFunctionComponent
函数节点子节点是通过函数执行返回获取的，所以函数组件的更新逻辑就是
1. 执行函数
2. Diff对比

需要注意，由于函数组件还有hooks需要处理，而hooks的实现逻辑是通过renderWithHook函数实现的，你可以把它简单的理解为执行了fiber.type 这个函数

我们知道 更新只可能发生在 HostRoot 或者 HostFunction这样的组件上的，所以这些组件还需要判断当前的更新发生完之后，得到的结果本身有无变化.

对于HostRoot组件，判断的是其对应的element子组件本身有无变化，函数组件判断的是其内部的state有无变化，这个是依靠一个全局变量didReceiveUpdate实现的，这个后面细说，你需要知道的是，函数组件内部需要二次检查是否需要bailout

实现如下:
```typescript
/** 处理函数节点的比较 */
function updateFunctionComponent(
  wip: FiberNode,
  Component: Function,
  renderLane: Lane
): FiberNode {
  // renderWithHooks 中检查，如果状态改变 则置didReceiveUpdate = true
  const nextChildElement = renderWithHooks(wip, Component, renderLane);
  if (wip.alternate !== null && !didReceiveUpdate) {
    // bailout
    // 重置hook
    bailoutHook(wip, renderLane);
    return bailoutOnAlreadyFinishedWork(wip, renderLane);
  }
  reconcileChildren(wip, nextChildElement);
  return wip.child;
}

```

## 更新Fragment组件
Fragment组件也很简单，你需要知道的是，对于Fragment组件，由于其有且仅有一个属性children，所以其props即pendingProps就是children，我们只需要
1. 从pendingProps中 获取子元素
2. 开启Diff 即可

```typescript
/** 处理Fragment */
function updateFragment(wip: FiberNode): FiberNode {
  /** fragment的pendingProps就是children */
  const nextChildElement = wip.pendingProps as ReactElementChildren;
  reconcileChildren(wip, nextChildElement);
  return wip.child;
}

```
